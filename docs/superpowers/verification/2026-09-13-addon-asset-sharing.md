# C5: asset sharing and SDK contract

The user’s choice of 13 September is implemented: several publications of the
same plugin can share a raster within the same privacy partition assigned by
the host. Each destination receives a distinct alias; the ImageIO /
CoreGraphics raster stays the same object and its pixels have a single reservation.

## Verified behavior

`AssetState.share` rechecks the source alias and its exact authority. Publisher,
addon, digest, connection and partition must match; feature and publication
may differ only through explicit sharing. Each new alias
reserves the usual 4,096 bytes of metadata, with no new decode or pixel copy.
Release, end or expiry of the source does not remove the other aliases and pins.
The last real reference determines the release of the raster quota.

`AddonRuntime.shareAsset` rechecks both publications before and after the
admission waits, protects pending metadata and drains deferred completions
before the final synchronous insertion. The partitions of the assignments are
immutable. `.addonOwned` covers self-produced data; `.isolated(UUID)` separates contexts
chosen by the host. The provider does not choose partitions in payloads, and the
document privacy remains redaction metadata, without granting authorizations.

The public `AssetHandle` contract reuses the existing validators and Foundation
Codable: seven closed fields, 8 KiB raw limit, owner consistent with PublicationID,
valid identifier, positive revision, positive dimensions within 1 MP and exact
RGBA8 bytes. Validation precedes any change to the canonical state. A constructed
or decoded handle is untrusted metadata, never an authorization.

`AddonAssetClient` exposes async import, sharing and release through
`AddonContext.assets`. The previous initializer remains available and fails
explicitly with `dependencyUnavailable` if an asset function is requested
without a client. No fake transport or in-process provider code was added.

Independent review of the three diffs concluded with no open findings. No codec,
parser or pixel-handling library was duplicated: Foundation, ImageIO/CoreGraphics
and the existing runtime components remain the shared implementations.

## Limits

macOS 27.0 beta 26A5425a, arm64, Swift 6.4/Xcode beta; deployment floor macOS 14
unchanged, with no execution evidence on the minimum OS. No signing qualification
for external addons, native transport, launcher or isolated decoder for hostile inputs.
The C0d gate remains unchanged and no tracing process was started.

The partitions verified here concern self-produced assets and host assignments;
they do not implement asset transfer from services or provenance tracking
of native bytes. Those paths must derive authority from the broker's canonical
grants/partitions. Handoff to the MainActor renderer, transport, cache and
restore remain. The overall C5 plan is not declared complete.
