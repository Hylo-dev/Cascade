## Wire and SDK decisions

Extend AssetTransferOperation with share/release. Share request contains source AssetHandle and target publicationID, release contains only source AssetHandle in addition to common schemaVersion/requestID/operation. No transferID/offset/bytes/totalBytes for these operations. Share response has result shared and only assetHandle; release response is acknowledged with no transferID. Failure remains exact bounded common fields. Existing constructors remain source compatible through optional source-handle argument. Existing imported/ack token rules remain unchanged. Validate share response owner equals source owner and target publication equals request target; imported response additionally checked against original begin publication in SDK. Exact JSON envelope field sets/null/unknown rejection and encoded worst-case bound must include two nested handles/publications without expanding196608 cap.

Expose SDK-only `AddonAssetMessageChannel: Sendable` with immutable generation:ConnectionGeneration and profile:AssetTransferFrameProfile?, `exchange(_ frame: Data, sequence: UInt64) async throws -> Data`, and idempotent `close() async`. This channel is a connection-bound byte interface, not an authenticated bootstrap by itself. Concrete channel MUST bound raw allocations before SDK decode, correlate physical generation/sequence, consume host response receipt and drain request/reply payload before exchange returns or throws; close must revoke its connection and drain outstanding exchange. Never infer physical rejection/disposal from cancellation alone. There is no production OS channel in this package; the real runtime is exercised by a test-only bridge implementing this contract.

Create public final `MessageAddonAssetClient: AddonAssetClient` with channel injection and one synchronous lock-gated operation slot covering import/share/release across all awaits. Derive generation/profile from channel, reject unsupported profile before exchange. No outgoing queue/history. Sequence starts0, increments checked per frame, never reused including failed attempts; every request UUID fresh. Encode using existing codec; decode and `validate(matching:)` every response. One import retains caller-owned <=1MiB input and copies only one <=65536 chunk at a time. Begin→ordered chunks→finish; transfer token kept only as bounded scalar. Whole operation exclusivity also holds through abort/close/drain.

SDK error semantics: local validation/busy rejection does not disturb active work. A valid host failure can be surfaced using bounded code after aborting a known active import if necessary; stale/expired transfer failure terminates that import. A malformed/mismatched reply or transport exception poisons the client, awaits channel close/drain, and never retries potentially completed finish/share/release. Cancellation between exchanges aborts a known transfer and drains the acknowledgment; if that exchange cannot complete, poison+close. Cancellation beforebegin sends nothing. Once a successful mutation response (finish/share/release) is known, return its known result rather than inventing an uncertain failure solely due to a late cancellation; do not leak a committed alias. Explicit close irreversibly revokes the client and channel; in-flight return checks must honor closure. Use bounded failure enums, no retained arbitrary error/Data history. Document transport responsibilities and limitations plainly.

## Canonical identity and lifecycle

Assignment currently has owner/publisher/digest/feature/privacy/authorityRevision but no immutable UUID (AddonRuntime.swift:35). Add assignmentToken UUID, minted once in both ordinary assignment (:496) and archive restoration (:2945), preserved on repeated assignment. Never derive it from mutable global authorityRevision.

Store one assembler and at most one scalar active binding/transfer ID in each ProcessRecord, created after processAdmissionBytes is prepaid, for both launch construction sites (:550,:4480). Include fixed assembler/record bookkeeping in that charge. No unbounded transfer table and no new process-independent assembler per begin.

Create AssetTransferBinding only from canonical connected process plus importAssetScope: incarnation, canonical connection token, exact publication ID, immutable assignment token. Revalidate the canonical installed identity/digest, resolution membership and connectedOwner after each suspension, just as storageConnection (:787) does. Begin uses request publication; subsequent frames use runtime-retained binding and verify current assignment token/scope again. Foreign transfer IDs must not clear the valid transfer. End/expiry/reassignment/disable/quiescence/stop/exit revoke eligibility; validation alone prevents alias escape, but also explicitly release idle assembly rather than retaining until process exit.

Reserve parser/envelope workspace via existing protected governor.withAssetDecodeReservation before takeAssetIngress. Launch staging prepaid capacity must cover asset codec's 196608-byte frame cap, bounded also by runtime configured maximumEnvelopeBytes; expose maximumAssetIngressBytes with zero default to adapters. Original raw.count must equal handle.encodedBytes. Decode exclusively with negotiated profile.

Retain bytes only inside the protected lexical execute helper; outward result contains bounded scalar outcome/reply disposition, not raw request/errors. Finish ingress once by exact successful taker; reject before take and preserve current duplicate claimant, following storage behavior. No assembler worker queues or retained history.

Use monotonic per-connection asset sequence >0, strictly greater than last accepted sequence, updated after authenticated parse and immediately before operation dispatch (including a failing backend operation). Request UUID is correlation, not replay protection. Shared slot does not require changing existing storage sequence semantics; a separate asset sequence is compatible and bounded.

Reply receipt binds host nonce/incarnation/canonical connection token/sequence/requestID/operation. ## Import/share/release commit

importAsset (:3747-3820) already has exact template: validate scope, assetState.importAdmissionBytes, growPool, revalidate, pendingAssetMetadataBytes, decode, revalidate, drain deferred cleanup if necessary, revalidate final scope, synchronous assetState.insert. Finish substitutes assembler.finish for assetDecoder.decode and validates immutable binding after every await. No second decode/copy. This must be an internal helper accepting existing AdmissionOperation because public import/share/release start admission themselves; nested beginAdmission fails. Factor minimal reusable core where practical.

Preserve pendingAssetMetadataBytes while asynchronous decode/deferred cleanup could shrink owner state; clear and shrink after failure. The raster's protected disposal remains independent of alias metadata. Returned host AssetState handle can use existing canonical asset metadata fields to construct CascadeContracts.AssetHandle.

Share wire request can carry exact source handle plus target publication, or minimal validated source alias/source publication/target publication. Reuse sharingAdmissionBytes and AssetState.share (:3826 onward), canonical immutable privacy partitions, fresh destination alias, no decoding. Full source-handle metadata is not authority. Release reuses assetScope/releaseImport/shrinkPool (:3904); release succeeds without allocating import metadata and does not revoke publication pins. Do not stub either SDK operation.

## Deadlines and revocation

Current DeadlineQueue has 3 aggregate stable keys (:316); nextDelay (:2436) refreshes publication/action/service. Add one stable aggregate asset deadline key and increase bounded maximumEntries to 4 (or combine into existing monotonic aggregate deliberately). Minimum across active assembler.nextDeadline; never per-transfer timer/task. serviceDeadlines explicitly expires assemblers; also close/revoke if associated assignment lost authority. Preserve fresh monotonic clock checks and exactly30s nonrenewable assembler semantics.

requestStop is synchronous (:2624), requestStopOnce synchronous (:4869), observeExit removes ProcessRecord and retains DeferredExit (:2301). Simply scheduling async assembler.close later is insufficient for immediate revocation while finish is in native decode. Split assembler synchronous invalidation from async cleanup, or have an explicit synchronous revocation token consulted by finish; retain protected cleanup ownership in process/deferred-exit records. Drain disposal through existing hasDeferredCleanup/drainDeferredCleanup (:4676,:4726), keeping a failed close observable/charged and avoiding infinite drain retry. Do not silently try? and drop the only handle if protected refund fails. Observed exit must retain assembler until close/disposal is accounted for. Finish native decode already owns its own cleanup, so closure must never refund its bytes early.

## Negotiation choice

Today negotiator upper bound is 1 if keyed storage supported, else0; storageFrameProfile is minor==1 (:17). Explicit1.2 asset capability is a routine extension of approved dedicated frame design, but choose coherent cumulative policy. Easiest preserve1.2 as cumulative: only advertise1.2 when asset adapter AND existing keyed storage capability exist; change storageFrameProfile to minor>=1 and asset profile minor>=2. This means assets require storage-capable assembly even though asset import does not require storage.own grant. If asset-only hosts must support1.2, negotiated capabilities must independently record actual storage support, else minor>=1 would falsely advertise storage. This is the only real API policy choice identified; defaults remain1.0 and storage-only assembly1.1. Untrusted protocol offers cannot enable host support.
